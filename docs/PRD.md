# PDF Viewer and Annotator — PRD and Technical Spec

Status legend: **[Implemented baseline]** = implemented in M1 (see [baseline verification](../README.md#baseline-verification)); **[Future]** = not built.

## 1. User and workflow

A document reviewer needs to inspect a local PDF and save review notes without signing in or uploading it. Single person, single machine, browser against a loopback server.

Workflow: start the local server → open the page → read a page in the preview → move between pages → write a titled note for the page → save → close everything → restart → the same note is shown for the same page.

## 4. Scope boundaries

Out at M1: opening arbitrary files, images, filters, rotation, region annotations, PDF writing, authentication, remote sync, deployment, paid services, external media, model integrations, print/authoring features, browser PDF plug-ins, evaluating PDF-embedded script.

## 5. System stack

Python 3.12 stdlib only (`http.server.ThreadingHTTPServer`, `sqlite3`, `unittest`); static HTML/CSS/native JS; no build tooling. Package `pdf_annotator`: `cli.py`, `server.py`, `storage.py`, `pdfgen.py`, `pdfparse.py`, `static/`.

Launch: `python -m pdf_annotator --data-dir <path> --port <port>` (Windows), `python3 -m ...` (Linux). Binds 127.0.0.1 only.

## 6. Contracts

Request/response and UI contract (authoritative):

### 6.1 API (all under 127.0.0.1)

| Endpoint | Result |
|---|---|
| `GET /` , `/app.css`, `/app.js` | Static allowlist; other paths 404 |
| `GET /api/v1/health` | `{"status":"ok","version":"0.1.0","schema_version":1}` |
| `GET /api/v1/document` | Display list parsed from generated bytes; 422 `unsupported_pdf` if parse fails |
| `GET /api/v1/document/file` | The fixture PDF bytes |
| `GET /api/v1/notes/{page}` | Note `{page,title,body,revision,updated_at}`; revision 0 if unsaved; 404 outside 1..2 |
| `PUT /api/v1/notes/{page}` | Body `{title<=120, body<=4000, base_revision}`; 200 note, 400, 403, 404, 409 with `current`, 413 (>16 KiB), 415 |

Errors: `{"error":{"code","message"}}`. Versioning: path prefix `/api/v1`; schema version in SQLite `user_version`; incompatible changes get `/api/v2`.

### 6.2 Schema

`notes(document_id, page, title, body, revision, updated_at)` primary key `(document_id, page)`, CHECK constraints on lengths, `revision >= 1`. Deterministic ordered migrations guarded by `user_version`; a newer database than the code refuses to start.

### 6.3 Algorithms

- **Parse**: find last `startxref`; read `xref` table; each in-use entry offset must start with `N G obj`; walk Catalog → Pages → Kids in order; read stream with `/Length` bounded by file size and the 8192-byte cap; tokenise content; reject operators outside `w RG rg re S f BT ET Tf Td Tj`. Limits: 64 KiB file, 10 pages, 500 ops/page, 200-char strings. No eval; no allocation from declared lengths.
- **Render**: client flips Y (`yCanvas = (pageHeight - y) * scale`), strokes/fills rects, `fillText` for text; accessible list built from the same ops.
- **Concurrency**: save succeeds only if `base_revision` equals stored revision, inside `BEGIN IMMEDIATE`; otherwise 409 with current note; the client keeps typed text and offers "Keep my text and save over" or "Use saved version".

### 6.4 UI

Two-pane workbench (preview | note) at ≥720 px, stacked below. Controls: Previous page, Next page, Note title, Page note, Save note, status region, conflict region, retry. Element ids: `page-canvas` (canvas), `page-text` (accessible text list), `prev-page`, `next-page`, `page-indicator`, `doc-title`, `doc-meta`, `note-title`, `note-body`, `save-note`, `status` (polite live region), `retry`, `conflict` (alert region), `conflict-keep`, `conflict-use-saved`. Display-list colors are 0..1 floats; coordinates are PDF user space (origin bottom-left), flipped by the client. Errors from the server and conflicts never discard typed text. System fonts, visible focus, contrast ≥ 4.5:1, labelled controls, no body overflow at 800x600 or 360 px wide.

## 7. Deterministic fixture and expected output

`build_sample_pdf()` produces the same bytes on each call; page size 300x200.

| Page | Ops (in order) |
|---|---|
| 1 | rect stroke (20,30,260,120) width 1; text "Platform map" at (20,170) size 18 |
| 2 | rect fill rgb(0.2,0.4,0.8) (30,40,40,20); rect stroke (20,30,260,120); text "Legend" at (20,170) size 18 (a `0 0 0 rg` resets fill to black before the text) |

## 8. Error, retry, restart, concurrency

- Network/5xx during save: text retained, `#retry` shown, status explains.
- 409: conflict region, no text dropped.
- Unsupported PDF: status message, page controls disabled.
- Restart: server reopens the same `annotator.sqlite3`; note reloaded on page view.
- Bad data dir (file, unwritable) or newer schema: exit code 2 with message.

## 9. Security and validation

Loopback bind only; Host must be 127.0.0.1/localhost with the served port; mutating requests also check Origin; no CORS headers; CSP with `script-src 'self'`; `nosniff`; `no-store`; JSON shape and length validation; 16 KiB write cap; static allowlist (no path joining); text rendered via `textContent`; SQLite constraints and transactions.

Items above are specified; execution results are not claimed here.

## 11. Sample demo

Start the server, open the URL, read "Platform map", press Next page to see "Legend", enter title "Check legend" and note text, Save note, stop the server, start again with the same data dir, open the page, go to page 2: the note is displayed.

## 12. Test plan

`python -m unittest discover -s tests` (stdlib). Parser round trip and rejection cases from in-test bytes; storage migrations and bad directories using disposable temporary roots; loopback API integration on port 0 including restart, conflicts, concurrency, header checks. Browser behavior is checked manually via the README smoke steps; no automated browser tests at M1.
